# Current React Bits Folder integration

Partner alone has a separate Sort button outside the Grid/List segmented control. Mine offers only Grid/List. Sort groups only the partner's existing priorities; no data or stored ordering changes.

The current TypeScript/CSS implementation from https://reactbits.dev/components/folder is vendored in Folder.tsx and Folder.css. The complete native spring, page and drag engine is retained. Source downloaded from https://github.com/DavidHDev/react-bits/tree/main/src/ts-default/Components/Folder. License: public/licenses/react-bits-folder.txt. The earlier simplified CSS revision is replaced. Minimal integration changes: the optional upstream image renderer uses unoptimized next/image with explicit dimensions; per-render engine-ref synchronization moves into the layout effect, and folder-depth CSS uses the matching pure render value, so this code works with React/Next lint rules. No rules were silenced. Solid mode uses the official default rendering path; glass/WebGL support is present but not enabled.

Opening one priority fades out the other folders and keeps the remaining live Folder instance in its original slot. Its actual wish previews are native draggable pages (up to the component's six-page limit). Preview clicks and grid-card clicks open normal wish details; dropping a preview changes only its temporary visual position, never the database. All wishes, including those beyond six previews, appear in the full grid below after their thumbnails finish loading or fail. Cards fly from the selected folder into measured grid positions, then become interactive. Existing Grid/List batch reveal and photo retry behavior remain.

Back or Escape restores all five priorities and returns focus to the opened folder. Empty folders show an empty message rather than fake documents. Outside clicks do not unexpectedly close the selected category. Native drag is disabled in reduced-motion mode; system reduced motion skips the grid flight as well. No migration, new dependency, upload or backend mutation.

Browser fixture tests render the actual WishlistPage with synthetic workspace data: Partner-only separate Sort, five colors, exclusive selected folder, Back/Escape, empty categories, native page pointer drag without opening a detail, card detail activation, reduced motion and no horizontal overflow at 320/375/430/768/1024/1920px. Physical touch-device testing remains outstanding.

## Stable selection position
Opening a lower-row folder previously removed preceding grid cells and collapsed the grid to one centered column. Motion animated that layout change, and document shrink could also move the viewport. Selection now captures the folder's existing slot in the click handler, preserves its x/y/width, reserves the previous section minimum height, and places Back outside layout flow. Other folders fade out, while the selected wrapper never receives a layout translation. Scroll anchoring is disabled only for this section. Cards still fly into the grid below the chosen row. No global overflow hiding or scroll-to workaround.

Empty groups now pass an actual empty items array to the current Folder engine. Its fallback uses demo documents only when items is omitted, not when items=[]; empty folders still animate their flap normally. The fixed profile header is a Motion layoutRoot with an isolated profile LayoutGroup, so document scrolling and folder layout notifications do not project the avatar from document coordinates. Profile hover expansion remains enabled.

Desktop image-page drag fix: browser-native image drag was intercepting pointer movement when a preview contained a real image (text-only previews did not reproduce it). Private thumbnails now set draggable=false, and Folder's stage prevents native HTML dragstart; the upstream pointer drag engine continues to run. A real blob-image mouse test verifies movement, release and no accidental detail opening. This does not reorder or save wish positions.
