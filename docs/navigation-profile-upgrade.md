# Navigation, partner profile and manual avatar cropping

Profile photos now pass through the existing manual 1:1 crop editor before Save. Selecting/cancelling a file does not upload it; drag/zoom and Use photo produce the square preview, and Save uploads it. The explicit legacy-browser-photo button opens the same crop flow. Existing authenticated/private upload and photo policies remain. Existing server avatars are not altered.

Nicknames now persist through PATCH /api/profile to the authenticated owner's profiles row, with trimming/1–32-character validation. GET /api/profile returns the owner's nickname and the paired member's current nickname/photo. Visible-tab polling/focus refresh keeps both current. The Partner page heading uses the partner's nickname, with Partner as a fallback until configured. Previously browser-local nicknames need one explicit save to become authoritative server values; appearance settings remain local.

Partner tab replaces the top-left Home button with the partner avatar, opposite the owner's avatar. It only expands on mouse hover, keyboard activation or mobile tap; it has no profile editor/actions. Escape, blur or mouse leave collapse it. The fixed header remains a Motion layout root with separate avatar groups.

Apply supabase/migrations/202611110001_partner_profile_photos.sql after the earlier profile-photos migration. It permits pair members to read only the partner's currently referenced avatar, while writes/deletes remain owner-only and stale objects remain private. No new table/columns are needed. This session does not run live migrations or deploy.

The old magnifying dock component/styles are removed. Current official React Bits GooeyNav TypeScript/CSS source is vendored in components/navigation, from https://github.com/DavidHDev/react-bits/tree/main/src/ts-default/Components/GooeyNav (https://reactbits.dev/components/gooey-nav). Its gooey/particle/WebGL engine and fallback are retained. Integration changes: Next Link instead of raw anchors, icon-only accessible labels, commit-phase ref updates for React compatibility and an explicit reduced-motion override. Four real links: Home / Partner / Mine / Discover; active state follows Next pathname and browser back/forward. License: public/licenses/react-bits-gooey-nav.txt. No UI framework or new dependency.

Folder overview reuses WishBatch to eagerly prepare its previews and reveal all folders together with the same 380ms fade/rise as card batches and respects reduced motion. Its stable selected-folder slot behavior remains. The three settings are retained because they control different things: Animations (formerly Fluid animations) is the motion master switch; Background motion (formerly Ambient animation) controls background motion within it; Reduce transparency controls surface opacity/blur and limits background visual intensity. Existing saved keys/preferences are preserved, and the new nav honors both motion and transparency preferences.

Automated browser checks cover current nav's four links, active state/back history, fallback without WebGL, reduced motion, no horizontal overflow at 320/375/430/768/1440px, desktop/mobile avatar expansion, manual square crop/cancel/save and nickname synchronization between isolated browser accounts. Profile API tests check owner-only nickname writes and authenticated current-partner photo reads. Live RLS/real-device verification follows the migration and deployment; neither is claimed by mock-backed tests.
